# Moving Games and Library Folder Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Steam games between libraries and non-Steam games between folders without Steam's window, and act on several games at once from a library folder's page in Preferences.

**Architecture:** A GTK-free `superlion/moving.py` plans and runs file jobs (move a Steam game, move a shortcut folder, delete a Steam game) with progress and per-job rollback. `superlion/ui/mover.py` runs a job list: closes Steam, runs jobs in a worker thread, applies pending changes and shortcut path rewrites, restarts Steam; while it runs, the window holds everything that writes to or starts Steam. The single Move dialogs and a new library folder subpage feed it.

**Tech Stack:** Python 3, GTK 4, libadwaita (PyGObject).

**Spec:** `docs/superpowers/specs/2026-11-19-move-design.md`

## Global Constraints

- Lean, human-looking code: no section banners, no docstrings restating names, comments only for what code cannot show.
- UI copy: formal British English, GNOME HIG (title case for headings and buttons, sentence case for body text).
- Test only with `./run-dev.sh` (`SUPERLION_DEVEL=1`, settings in `~/.config/superlion-devel`); never touch `~/.config/superlion` or the installed app.
- No computer-use. Off-screen scripts for widgets; Tom checks anything visual and any real move or delete.
- No test suite exists. Pure functions get a plain `python3 -I` assertion script in the scratchpad, working on temporary directories only, never real libraries.
- GUI runs under `dbus-run-session`/headless need a private `XDG_RUNTIME_DIR` (`rt=$(mktemp -d) && chmod 700 "$rt"`, removed afterwards).
- Steam must be closed while any manifest moves or is deleted, or `shortcuts.vdf` is written.
- Commits carry no Claude co-author line.

## Review Focus

- Proton prefixes contain symlinks (`pfx/dosdevices/c:` → `../drive_c`, `z:` → `/`): copying must copy links as links, never follow them (following `z:` copies the whole filesystem). Test in Task 2.
- A copy that fails part-way (disk full): the partial copy is removed, the originals and manifest are untouched, later jobs still run. Test in Task 2.
- Source and destination on the same drive under different paths (bind mounts, `/home` and `/home/tom/...`): decided by `st_dev`, so it renames instead of copying. Test in Task 2.
- Shortcut paths: `Exe` is quoted (`"/mnt/ssd/Games/X/x.exe"`), `StartDir` may lack a trailing slash (`/mnt/ssd/Games/FFVII Remake`) or be `./`; replacement only at a path boundary, so `/mnt/ssd/Games/X` does not match `/mnt/ssd/Games/X2`. Test in Task 3.
- Steam closed before the job list: it stays closed, and queued pending changes are written before the path rewrites. Steam running before: it is started hidden even when every job failed. Check in Task 4.

### Task 2: Steam game jobs in `moving.py`

**Files:**
- Create: `superlion/moving.py`

**Interfaces:**
- Produces:
  - `steam_parts(library: Path, appid: int, installdir: str) -> list[Path]` — existing paths under `<library>/steamapps`, in move order: `common/<installdir>`, `compatdata/<id>`, `shadercache/<id>`, `workshop/content/<id>`, `workshop/appworkshop_<id>.acf`, `appmanifest_<id>.acf` last.
  - `parts_size(paths: list[Path]) -> int` — bytes, not following symlinks.
  - `same_drive(a: Path, b: Path) -> bool` — `st_dev` of `a` and of `b` (or its nearest existing parent).
  - `class Progress` — `done: int`, `total: int`, `label: str`, `cancelled: bool`; written by the worker, read by the UI.
  - `move_steam_game(source: Path, target: Path, appid: int, installdir: str, progress: Progress) -> None` — raises `MoveError(message)` after rolling back; checks every destination is free before touching anything.
  - `delete_steam_game(library: Path, appid: int, installdir: str, progress: Progress) -> None` — manifest first, then the rest.
  - `library_contents(library: Path) -> list[dict]` — `{"appid", "name", "installdir", "size", "tool"}` from the folder's manifests; `size` is `SizeOnDisk`; `tool` from `library.is_tool(name)`.
  - `class MoveError(Exception)`.

- [ ] **Step 1:** Assertion script in the scratchpad building two fake libraries in a temp dir (game folder with a nested file, a `compatdata/<id>/pfx/dosdevices` with a relative symlink `c:` → `../drive_c` and an absolute one `z:` → `/`, a shader cache, a manifest). Assert:
  - `steam_parts` lists the existing parts with the manifest last and skips missing ones;
  - after `move_steam_game` with copying forced (monkeypatch `same_drive` to return False), every part exists under the target, the symlinks are still symlinks with the same targets, and nothing is left at the source;
  - the same with `same_drive` True (rename path);
  - a pre-existing `compatdata/<id>` at the target raises `MoveError` naming it, and nothing moved;
  - a copy that raises `OSError(ENOSPC)` on the second file (monkeypatch the chunk copy) raises `MoveError`, removes the partial target, leaves the source intact;
  - `progress.done == progress.total` after a copy;
  - `delete_steam_game` removes the manifest first (monkeypatch a failure after it: manifest gone, folder may remain) and everything when it succeeds;
  - `library_contents` returns the fake game with its size.
- [ ] **Step 2:** Run it: `python3 -I <script>`; expect ImportError.
- [ ] **Step 3:** Implement. Copy with `os.scandir` walking, `os.symlink(os.readlink(...))` for links, files in 1 MiB chunks adding to `progress.done`, `shutil.copystat`; check `progress.cancelled` between chunks and raise `MoveError("Cancelled")`. Order across drives: copy all parts but the manifest, copy the manifest, then delete the source parts. Same drive: `os.rename` each, undoing earlier renames on failure.
- [ ] **Step 4:** Run the script; expect all assertions to pass.
- [ ] **Step 5:** Commit: "Move and delete Steam games' files".

### Task 3: Shortcut folders and path rewrites

**Files:**
- Modify: `superlion/moving.py`
- Modify: `superlion/steam_settings.py`

**Interfaces:**
- Consumes: `library.read_shortcuts(config)`, `library.field(entry, name)`, `steam_settings._write_atomic`.
- Produces:
  - `shortcut_exe(entry) -> Path | None` — first `shlex` word of `Exe` when it is an absolute existing path, else None.
  - `suggest_folder(entries: dict[int, dict], appid: int, blocked: list[Path]) -> tuple[Path, list[int]] | None` — the highest folder above the executable that holds no other shortcut's executable and is not home, a mount point (`os.path.ismount`) or inside any path in `blocked` (the Steam libraries' `steamapps`); when the executable's own folder fails, that folder and the app IDs whose executables are under it. None when `shortcut_exe` is None.
  - `sharing(entries, appid, folder: Path) -> list[int]` — other app IDs whose executable is under `folder` (used when Tom picks a parent).
  - `rewrite_entry(entry: dict, old: Path, new: Path) -> dict` — replaces `old` at a path boundary in `Exe`, `StartDir`, `icon` and `LaunchOptions` (keys matched case-insensitively, original key spelling kept).
  - `move_folder(old: Path, new_parent: Path, progress: Progress) -> Path` — same rollback and progress rules as Task 2; returns the new path; `MoveError` if `new_parent` is inside `old` or `new_parent/old.name` exists.
  - `steam_settings.rewrite_shortcut_paths(config, moves: dict[int, tuple[Path, Path]]) -> None` — loads `shortcuts.vdf`, applies `rewrite_entry` to each app ID's entry, writes it with `_write_atomic(..., binary=True)`.

  - `rewrite_entry` on `Exe` `"/g/X/x.exe" -v --proj-path "/g/X/data"`, `StartDir` `/g/X`, `LaunchOptions` `PROTON_LOG=1 %command% /g/X/mods`, `icon` `/g/X2/i.png`, moving `/g/X` → `/h/X`: the first three change, the icon does not;
  - `move_folder` refuses a destination inside the source.

### Task 4: Job runner and holding Steam

**Files:**
- Create: `superlion/ui/mover.py`
- Modify: `superlion/ui/window.py`
- Modify: `superlion/app.py`

**Interfaces:**
- Consumes: Task 2 and 3 functions; `steam_control.is_running/running_games/shutdown/start`; `pending.apply_now`; `window.toast/reload/find_game`; `will_close_text`.
- Produces:
  - `Job(kind: str, name: str, run: Callable[[Progress], None], size: int, shortcut_moves: dict[int, tuple[Path, Path]] = {})` — `kind` is `"move"` or `"uninstall"`.
  - `Mover(window)` GObject with signals `progress(label: str, done: int, total: int)` and `finished(failures: list[tuple[str, str]])`, property `busy: bool`, method `start(jobs: list[Job], parent, verb: str)` (`verb` "Move" or "Uninstall" for "Close Steam and Move").
  - `window.mover` and `window.moving -> bool`.

- [ ] **Step 1:** `Mover.start`: Steam running and `running_games()` empty → close it; something running → `Adw.AlertDialog` "Steam Must Be Closed", body `will_close_text(names)` with names as in `write_to_steam`, responses Cancel / "Close Steam and <verb>"; Steam closed → go on. Remember whether Steam was running, and toast "Moving <name>…" ("Moving 2 games…", "Uninstalling 2 games…") as the jobs start.
- [ ] **Step 2:** Run jobs in one `threading.Thread`; a `GLib.timeout_add(250)` reads the shared `Progress` and emits `progress` with "Moving <name> (1 of 2)…" (or "Uninstalling…"); failures are collected as `(name, message)` and the next job runs.
- [ ] **Step 3:** On the main thread after the last job: `pending.apply_now`, then `steam_settings.rewrite_shortcut_paths` with every successful job's `shortcut_moves`, `grant_flatpak_access` for new folders Steam cannot read (`shortcuts.steam_can_read`); `steam_control.start` if Steam was running before; `window.reload()`; toast "<name> moved to <dest>" / "2 games moved to <dest>" / "2 games uninstalled"; an `Adw.AlertDialog` "Some Games Could Not Be Moved" listing failures when any. Emit `finished`.
- [ ] **Step 4:** In `window.py`, while `self.moving`:
  - `_on_pending_watch` returns `SOURCE_CONTINUE` without writing;
  - `write_to_steam` calls `queue()`, `on_applied()` and toasts "Saved. Steam gets this when the move finishes.";
  - `launch`, `install_game`, `uninstall_game`, `start_updates`, `relaunch_steam` toast "Steam starts when the move finishes" and return.
- [ ] **Step 5:** Quit guard: the window's `close-request` and `app.quit` (in `app.py`) ask "A Game Is Being Moved" (body: "Quitting stops the move and puts the game back where it was.", responses Cancel / Quit, destructive) when `window.moving`; on Quit set `progress.cancelled`, and quit once `finished` fires.
- [ ] **Step 6:** Off-screen check script: build a `Mover` with two fake jobs over temp dirs (one failing), Steam treated as closed (monkeypatch `is_running` False), run a `GLib.MainLoop` until `finished`; print the signals received. Expected: progress labels "(1 of 2)" and "(2 of 2)", one failure, files moved for the other.
- [ ] **Step 7:** Commit: "Run moves with Steam closed and hold Steam until they finish".
